# Idea: PRODUCT NAME
Write freely. Nothing here is a commitment; `/define-mvp` reads this and cuts the MVP from it.

## What is it?
One paragraph: what the product does and why it should exist.

## Who uses it?
The people using it, and the situation they are in when they open it.

## Everything it could do
List every feature you can think of, big or small. Order does not matter.

## Data and backend
APIs, services or databases it will use. Link docs or OpenAPI specs. Say which need a key
(keys go in `.env.local`, never in this file).

## Platforms
Desktop web, mobile web, native app? Any must-have device or orientation?

## Look and feel
Design system to use, brand rules, reference apps or screenshots you like.

## Constraints
Deadlines, compliance or legal rules, things it must never do.

## Success
How you will know it is working for users.
